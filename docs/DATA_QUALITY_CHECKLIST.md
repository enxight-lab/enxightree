## A. 데이터 수집·정제 규칙 (수집기에 반드시 구현)

### A-1. 실거래가 API 필터링 — 4대 필수
- [x] ✅ **해제건 제외**: cdealType='O' 또는 해제일(cdealDay) 존재 → 제거 (실거래가 띄우기 수법 방어)
- [x] ✅ **직거래 분리**: dealingGbn='직거래'(가족 간 증여성 저가) → 집계 제외
- [x] ✅ **신고 시차 처리**: 계약 후 30일 내 신고 → 전월 데이터도 익월 말까지 "잠정" — `asof.trade_provisional` + 화면 고지. 매일 cron 재수집으로 자동 확정
- [x] ✅ **소표본 가드**: 월 거래 5건 미만 지역은 대표가 비표시("표본 부족") + 건수 병기

### A-2. 지표 선택 기준
- [x] ✅ 히트맵 **색상(변동률)** = R-ONE 가격지수 — 평균가 변화 사용 금지
- [x] ✅ 대표가는 **거래 건수와 반드시 세트**로 표시 (건수 없는 평균은 무의미)
- [x] ✅ 평균 대신 **중위가격** 표시 (거래 믹스 효과 — 고가 단지 편중 거래 → 평균 착시 방어)
- [x] ✅ 면적·단위: 전용면적 혼합 중위가임을 화면 각주에 명시 (㎡당 정규화는 백로그)

### A-3. 출처 교차검증
- 📋 부동산원 ↔ KB시세는 표본·방법론이 달라 방향이 다를 수 있음 → 발행 시 출처·기준일 병기
- 📋 단일 출처 단정 금지, 괴리가 클 땐 양쪽 다 제시
- [x] ✅ 화면 푸터에 출처 + 지수/실거래 기준 시점 병기

### A-4. 행정구역 변경 감시 (파이프라인 지뢰)
- 특별자치도 전환, 시군구 통합·편입(예: 군위→대구) 시 법정동 코드·GeoJSON 경계 어긋남
- [x] ✅ 수집기-지도 조인 키는 행정코드 기반 (`src/data/geo.js` KOSTAT + `scripts/lawd_codes.json` 법정동)
- [ ] 🔜 **연 1회 이상 행정표준코드(code.go.kr) 대조** → `python scripts/gen_lawd_codes.py` 재실행 + geo.js 예외 테이블 점검 (다음 점검: 2027-06)

### A-5. 전세 데이터 (추후 전세 모드 시)
- 🔜 갱신계약(5% 상한) / 신규계약 반드시 구분 — 혼합 평균은 왜곡
- 🔜 전세가율 고지역 = 역전세·보증금 미반환 리스크 신호로 맥락 해석

## B. 콘텐츠 발행 기준 (ENXIGHT 룰 — 뉴스·매거진 연계 시)

- 📋 **기준일 명시**: 규제지역, 토지거래허가구역, LTV/DSR, 세제 언급 시 "○월 ○일 기준" 없으면 발행 금지
- 📋 **호가 ≠ 실거래가**: 네이버 매물가(호가)와 실거래가를 문장 안에서 명확히 구분 (본 앱은 실거래·지수만 사용)
- 📋 **투자권유 표현 금지**: "지금이 바닥", "○○ 사야 할 때" 등 매수 단정 표현 배제
- [x] ✅ **잠정치 고지**: 최근 월 실거래 인용 시 신고 시차 각주 — 화면 자동 표시
- [x] ✅ **출처·한계 각주**: 모든 수치에 출처 + 기준일 + 알려진 한계

## C. 한 줄 요약 — 최소 방어선 3가지

1. ✅ 해제건 안 거른 실거래가 쓰지 않기
2. ✅ 거래 건수 없는 평균가 쓰지 않기 (중위가 + 건수 병기)
3. 📋 기준일 없는 제도 언급 하지 않기 (콘텐츠 단계)

*이 세 가지만 지켜도 시중 부동산 콘텐츠 대부분보다 정확하다.*
