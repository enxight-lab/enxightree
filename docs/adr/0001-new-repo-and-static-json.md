# ADR 0001 — 별도 repo + 정적 JSON(주기 배치) 채택

- **상태**: Accepted
- **일자**: 2026-06-10 (KST)
- **맥락 세션**: ENXIGHT-DESK 신설

## 배경

ENXIGHT 홈페이지(`enxight.com`)에 부동산·주식 등 시장 정보를 조회하는 화면이 필요.
요구: "일단 웹에서 정보 조회만, 이후 앱으로 확장."

홈페이지(`enxight-lab/ENXIGHT-HOMEPAGE`)는 Cloudflare Workers **Static Assets only**
(`wrangler.toml` 에 `main` 없음) — 백엔드 함수가 없다.

## 결정

1. **별도 repo `enxight-lab/ENXIGHT-DESK`** 로 분리 (서브도메인 `desk.enxight.com`).
   - 사유: "앱으로 키운다"는 목표 → 나중에 백엔드(Worker/API 프록시/DB)를 자유롭게 붙이려면
     콘텐츠/홈페이지 배포와 분리된 그릇이 유리. 홈페이지 섹션으로 시작 후 이전하는 재작업 회피.
2. **데이터는 주기 배치 → 정적 JSON**.
   - 사유: 부동산 공공 API 등은 키가 필요 → 클라이언트 노출 불가. 배치(서버측)에서만 키를 쓰고
     산출물(정적 JSON)만 배포하면 키 노출 없이 정적 사이트로 굴릴 수 있다.
   - 주식 데이터는 매거진 파이프라인이 이미 수집 → 산출물 재사용 우선.
3. **현 단계 백엔드 없음**. `wrangler.toml` 은 홈페이지와 동일한 Static Assets only.

## 결과

- 장점: 정적이라 운영 단순·키 안전·패밀리룩 즉시 상속. 앱 확장 시 같은 repo 에 함수만 추가.
- 비용: 실시간성 약함(배치 주기에 의존). GitHub repo·서브도메인·CF 프로젝트 신규 셋업 1회.

## 확장 트리거 (이때 백엔드 도입 재검토)

- 사용자 입력 기반 즉석 조회(임의 주소/종목 검색)가 핵심 기능이 될 때
- 실시간성이 배치 주기로 감당 안 될 때
- 개인화/저장/알림 등 상태가 필요할 때

→ 같은 repo 에 `main = "worker/index.js"` + API 프록시 추가, 또는 별도 데이터 API.
